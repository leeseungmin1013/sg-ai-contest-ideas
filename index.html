여러 개의 아이디어를 각각 제출 가능한 구현제안서 수준으로 고도화했습니다.

구현제안서 양식의 일반 사항, 기술 명세, 구현 방법 및 계획을 기준으로 7개 아이디어를 모두 재정리했습니다. 팀은 이 페이지에서 후보를 비교하고, 각 아이디어를 별도 제안서로 확장할 수 있습니다.

작성 프레임

양식은 표지 제외 5장 이내입니다. 그래서 모든 아이디어는 같은 평가 항목으로 빠르게 압축되어야 합니다.

핵심 작성 방향: 기술 설명보다 먼저 대학 현장 문제를 분명히 쓰고, 생성형 AI가 왜 필요한지, 어떤 MVP를 만들 수 있는지, 서강 데이터·제도·학생 경험과 어떻게 연결되는지 보여줘야 합니다.

1. 일반 사항

기술명, 분야, 제안배경, 소요기간, 유사기술, 차별점. 심사자가 첫 장에서 문제와 제출 분야를 바로 이해해야 합니다.

2. 기술 명세

기술목적, 구조, 주요기능, 결과물 형상, 배포방식, 혁신성, 도전성. 생성형 AI가 어떤 판단과 설명을 맡는지 구체화합니다.

3. 구현 방법 및 계획

최소 3개 세부 업무, 주차별 구현 계획, 기술스택. MVP 범위를 작고 검증 가능하게 잡는 것이 중요합니다.

1

Sogang Socratic AI TA

강의자료와 과제 가이드라인을 기반으로 학생에게 정답 대신 단계별 힌트와 유도 질문을 제공하는 AI 조교.

⑤ 학습 지원·AI 활용 교육 ① 교육 혁신 MVP 4~6주

일반 사항

제안배경학생은 과제 오류에 막히면 일반 ChatGPT로 정답을 얻기 쉽고, 학습 과정이 생략됩니다. 대학은 AI 사용을 금지하기보다 윤리적 활용을 훈련할 도구가 필요합니다.
유사기술ChatGPT, GitHub Copilot, Khanmigo, LMS Q&A.
차별점과제별 허용 범위와 교수자 정책을 반영해 전체 정답 대신 질문, 작은 테스트, 개념 확인을 우선 제공합니다.

기술 명세

  • 과제 정책 필터: 전체 풀이 금지, 부분 힌트 허용, 테스트 케이스 허용 수준을 설정합니다.
  • 단계형 힌트: 오류 메시지 해석, 개념 확인, 의심 위치 안내, 최소 수정 방향을 순차 제공합니다.
  • 교수자 리포트: 개인 정답이 아닌 익명화된 공통 오류 유형과 난점 Top 5를 제공합니다.
  • 결과물: 학생용 챗봇, 교수자 대시보드, 과목별 정책 콘솔.

구현 계획

구현범위Python 기초 과제 1개, 코드·오류 입력 UI, 힌트 생성 파이프라인, 정답 방지 필터, 오류 리포트.
일정1주차 정책·사례 수집, 2~3주차 RAG·챗 UI, 4주차 필터·로그, 5~6주차 사용성 테스트.
기술스택React/Next.js, FastAPI, LLM API, LangChain/LlamaIndex, PostgreSQL, pgvector 또는 Chroma.
2

Reading Pace AI

페이지 수가 아니라 학생의 사전지식과 이해도를 기준으로 학습 순서와 속도를 조정하는 AI 학습 매니저.

⑤ 학습 지원·AI 활용 교육 ① 교육 혁신 MVP 4~6주

일반 사항

제안배경학생은 긴 자료를 읽을 때 무엇을 이해해야 하는지보다 분량에 끌려가기 쉽습니다. 기존 플래너는 일정 중심이라 이해도 기반 조정이 어렵습니다.
유사기술Notion AI, ChatPDF, Quizlet, 일반 학습 플래너.
차별점문서 요약에서 끝나지 않고, 퀴즈 결과에 따라 다음 학습 순서와 분량을 재조정합니다.

기술 명세

  • PDF/강의노트 구조 분석과 핵심 개념 추출.
  • 사전지식 진단 퀴즈, 1분 이해도 체크, 복습 카드 생성.
  • 3일·7일·14일 학습 계획과 오답 기반 페이스 재조정.
  • 결과물: 웹 플래너, 개인별 학습 캘린더, 퀴즈 카드, 복습 리포트.

구현 계획

구현범위PDF 업로드, 텍스트 추출, 개념·난이도 태깅, 학습 계획 생성, 퀴즈 기반 재조정.
일정1주차 샘플 자료 선정, 2~3주차 분석·퀴즈 파이프라인, 4주차 UI, 5~6주차 테스트.
기술스택React, FastAPI, PDF 파서, LLM API, RAG, PostgreSQL, 캘린더 UI.
3

Sogang Course Architect

졸업요건, 시간표, 선수과목, 자기설계전공, 진로 목표를 함께 고려해 학기 수강 전략을 추천하는 에이전트.

① 교육 혁신 ④ 학생생활·캠퍼스서비스 MVP 5~8주

일반 사항

제안배경수강신청은 졸업요건, 복수전공, 시간표 충돌, 선수과목, 진로 목표를 동시에 고려해야 하는 복잡한 의사결정입니다.
유사기술에브리타임 시간표, 학사포털 졸업요건 조회, 일반 시간표 생성기.
차별점단순 시간표 앱이 아니라 서강의 자기설계전공과 융합 교육 특성을 반영한 학업 경로 설계 도구입니다.

기술 명세

  • 이수 과목 기반 졸업요건 자동 점검.
  • 공강 선호, 이동 시간, 난이도 분산을 반영한 후보 시간표 생성.
  • 자기설계전공·복수전공 경로와 실패 시 플랜 B 제공.
  • 결과물: 수강 설계 웹앱, 졸업요건 리포트, 후보 시간표 카드.

구현 계획

구현범위특정 전공 1~2개, 요건표 구조화, 이수 과목 수동 입력, 시간표 후보 3개, 위험요소 설명.
일정1~2주차 데이터화, 3~4주차 계산·조합 엔진, 5~6주차 설명·UI, 7~8주차 사례 테스트.
기술스택React, TypeScript, FastAPI, PostgreSQL, OR-Tools 또는 자체 조합 알고리즘, LLM 설명 생성.

Sogang Policy GPT

학칙, 내규, 장학, 등록금 환불, 휴복학 규정을 통합 검색하고 조항·페이지 근거와 함께 답변하는 AI.

③ 행정·운영 혁신 ② 연구 지원 MVP 3~5주

일반 사항

제안배경학사·장학·환불·휴복학 규정은 여러 PDF와 웹페이지에 흩어져 있고, 학생과 직원 모두 근거 조항을 찾는 데 시간이 걸립니다.
유사기술대학 FAQ 챗봇, 사내 규정 검색 봇, ChatPDF, 일반 RAG 챗봇.
차별점학생용 쉬운 설명과 직원용 조항 중심 모드를 분리하고, 답변마다 문서명·조항·페이지·링크를 표시합니다.

기술 명세

  • 휴학, 복학, 장학, 등록금 환불 규정 통합 검색.
  • 근거 인용 답변과 담당 부서 확인 필요 플래그.
  • 반복 질문 통계와 문서 공백 리포트.
  • 결과물: 웹 챗봇, 문서 업로드 콘솔, 답변 근거 뷰어.

구현 계획

구현범위4개 규정 영역, PDF 파싱, RAG 검색, 출처 인용, 학생용/직원용 모드.
일정1주차 문서 수집, 2주차 RAG 구현, 3주차 모드·플래그, 4~5주차 오답 개선.
기술스택FastAPI, React, LlamaIndex/LangChain, PostgreSQL/pgvector, PDF 파서, LLM API.

내 취향 알바트로스

동아리, 세미나, 비교과, 장학, 공모전, 채용 설명회를 학생 관심사에 맞춰 추천하는 AI 피드.

④ 학생생활·캠퍼스서비스 ⑥ 캠퍼스·사회 혁신 MVP 3~5주

일반 사항

제안배경학교·학과 공지, 비교과, 인스타그램, 카카오톡방, 이메일에 정보가 흩어져 학생은 자신에게 맞는 기회를 놓치기 쉽습니다.
유사기술학교 공지사항, 비교과 시스템, 에브리타임 게시판, 뉴스레터.
차별점공지 모음이 아니라 관심사·진로 목표 기반 기회 발견 피드이며, 추천 이유와 마감일을 함께 보여줍니다.

기술 명세

  • 공지 자동 수집 또는 수동 업로드와 정보 구조화.
  • 행사명, 날짜, 대상, 마감일, 신청 링크 태깅.
  • 관심 키워드 기반 추천, 주간 뉴스레터, 마감 전 알림.
  • 결과물: 웹 피드, 관리자 업로드 페이지, 개인화 뉴스레터.

구현 계획

구현범위공식 공지와 학과 공지 일부, CSV 업로드, 유형 태깅, 관심 키워드 5개 추천, 뉴스레터.
일정1주차 샘플 수집, 2주차 구조화·업로드, 3주차 추천 피드, 4~5주차 알림·테스트.
기술스택Next.js, Supabase/PostgreSQL, LLM 정보 추출, 추천 알고리즘, 이메일 API.

Albatross Career Mentor

이력서, GitHub, 관심 직무, 수강 이력을 분석해 부족 역량과 교내 프로그램, 선배 사례, 모의면접을 연결하는 AI 진로 코치.

④ 학생생활·캠퍼스서비스 ① 교육 혁신 MVP 5~7주

일반 사항

제안배경학생은 어떤 직무가 맞는지, 무엇을 더 준비해야 하는지, 어떤 교내 자원을 활용해야 하는지 알기 어렵습니다.
유사기술LinkedIn, 원티드, 잡플래닛, ChatGPT 이력서 피드백, 대학 취업지원 시스템.
차별점외부 직무 추천을 넘어 서강의 강의, 비교과, 연구실, 세미나, 멘토링 자원으로 다음 행동을 연결합니다.

기술 명세

  • 이력서·GitHub·활동 내역 기반 역량 추출.
  • 직무별 역량 체크리스트와 차이 분석.
  • 교내 자원 추천, 유사 선배 사례, 모의면접 피드백.
  • 결과물: 진로 코치 웹앱, 역량 리포트, 추천 자원 카드.

구현 계획

구현범위직무 3개, 학생 프로필 입력, 이력서 분석, 역량 체크리스트, 교내 자원 샘플 매칭, 모의면접.
일정1주차 기준표 구성, 2~3주차 리포트, 4~5주차 자원 매칭, 6~7주차 모의면접·보안 UX.
기술스택React, FastAPI, LLM API, PostgreSQL, 텍스트 파서, 임베딩 검색, 익명 세션.

AI 사용이 보편화된 시대의 팀플, 보고서, 질문, 정책 문제를 데이터 기반으로 진단하고 개선하는 인사이트 플랫폼.

③ 행정·운영 혁신 ⑤ 학습 지원·AI 활용 교육 ⑥ 캠퍼스·사회 혁신 MVP 5~8주

일반 사항

제안배경AI 사용을 무조건 금지하기 어려운 상황에서 팀플 무임승차, 보고서 출처 검증, 묻지 못한 질문, 정책 영향 예측을 개선할 도구가 필요합니다.
유사기술Turnitin, Copyleaks, Slack/Notion AI 요약, 설문 분석 도구, BI 대시보드.
차별점감별과 처벌 중심이 아니라 과정의 투명성, 질문 회복, 학습 개선을 중심으로 설계합니다.

기술 명세

MVP 후보기능장점난점
묻지 못한 질문 큐레이터익명 질문 수집·클러스터링프라이버시 부담 낮음참여 유도 필요
AI 사용 가시화 평가프롬프트·수정·검증 과정 분석시대성 강함공정성 설계 필요
팀플 코파일럿회의록·액션 아이템·기여 신호학생 체감 문제 강함감시 논란 관리
claim 검증보고서 주장과 출처 대조글쓰기 교육과 연결외부 DB 연동 난도

구현 계획

추천 구현범위묻지 못한 질문 큐레이터 + AI 사용 가시화 평가 미니 루브릭.
일정1주차 윤리 원칙, 2~3주차 질문 수집·클러스터링, 4~5주차 루브릭·대시보드, 6~8주차 파일럿.
기술스택Next.js, FastAPI, LLM API, 임베딩 클러스터링, PostgreSQL, 차트 라이브러리, 권한 관리.

공통 윤리·보안 원칙

여러 제안서에 반복해서 넣을 수 있는 안전장치입니다. 특히 학생 친화 분야는 감시보다 지원의 언어가 중요합니다.

원칙적용 방식
최소 수집기능에 필요한 정보만 입력받고 민감정보는 선택 입력으로 둡니다.
근거 표시규정, 강의자료, 공지 등 출처가 필요한 답변에는 문서명과 링크를 표시합니다.
책임 경계행정·진로·평가 판단은 AI가 최종 결정하지 않고 담당자 확인 절차를 둡니다.
투명성추천 이유, 데이터 출처, 업데이트 날짜, 불확실성을 화면에 표시합니다.
학생 친화성감시·통제보다 학습 지원, 기회 발견, 자기주도성 강화를 중심 메시지로 둡니다.

팀 회의 체크리스트

각 아이디어를 실제 제안서로 옮기기 전에 아래 항목만 채워도 완성도가 크게 올라갑니다.

  • 각 아이디어를 어느 공모 분야로 낼 것인가?
  • 같은 팀이 여러 개를 낼 때 서비스명이 서로 구분되는가?
  • 각 제안서의 MVP 범위가 5장 이내에서 설명 가능한가?
  • 실제 데모에 사용할 샘플 데이터는 무엇인가?
  • 서강 특화 요소가 서비스명, 데이터, 시나리오에 드러나는가?
  • 개인정보, 평가 공정성, AI 오남용 방지 정책이 한 문단 이상 들어갔는가?
  • 발표 첫 30초에 학생 경험 기반 Hook이 있는가?
  • 기술적으로 멋짐보다 대학 현장 문제 해결이 먼저 보이는가?
